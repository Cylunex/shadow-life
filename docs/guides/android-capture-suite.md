# Android 录音、地点、订单与回顾

功能入口：记录 → 录音、截图与自动记录，或首页采集概览。采集页分为“采集”“应用与活动”“分析与设置”；应用使用与自动屏幕文字的授权在“应用与活动”。

## 录音

从可见页面开始录音，支持暂停、继续与结束，前台通知也提供控制。麦克风由系统限制或其他录音占用、账号切换时结束当前录音；进程终止后不自动重启麦克风。

本机以 16 kHz 单声道 PCM 录制，每 90 秒封存。PCM、元数据和上传附件在磁盘上均绑定账号加密；WAV 仅在内存中形成并传给既有加密附件队列。已经封存的片段可恢复；最后一个片段只有完整性校验通过后才恢复，不补出未录到的时间。

同步后，原音频可回听。处理器返回的分段时间戳可以跳转播放；用户更正保留修订，旧处理尝试不能覆盖新修订。失败提供重试，未配置处理器时明确显示等待配置。删除后隐藏转写与该录音原件访问，相同片段身份重传不能复活；用户主动另存的资料副本保留。

### 转写配置

处理器兼容 `multipart/form-data` 音频转写协议，要求 `verbose_json` 的 `segments` 含 `start`、`end` 和 `text`，可选字符串 `speaker`。不把无时间戳的整段文本编造成分段。

- [脱敏配置示例](../../server/worker/config/transcript.example.json)。实际 JSON 放在仓库外，`SHADOW_TRANSCRIPT_CONFIG_FILE` 仅指定其路径；API 和 Worker 使用同一配置路径以显示一致状态。
- `url`、`model` 为必填；`token_file` 为可选的凭据文件路径；`language` 可选；`timeout_ms` 默认 120000，最多 180000。
- 凭据放在既定 secrets 目录，目录权限 0700、文件 0600。不要将真实地址、配置或密钥放进仓库。
- 除本机回环 HTTP 外要求 HTTPS。按配置向处理器发送音频；开发测试使用本机合成响应，不调用真实模型。

## 停留地点

主动开始后以原生定位前台服务观察，坐标精度需在 100 米以内，至少三次采样、持续五分钟才产生停留。距离超过 100 米或采样断开五分钟会切段；同地点每三十分钟封存，连续采样的封存区间共享实际观测边界。

保存坐标、精度、实际开始／结束时间和原始时区；不把附近商家推断为已到访。用户填写的地点名称用于当前地点，移动到新地点后恢复通用名称。中断检查点与待同步停留加密保存；开启新记录会先保留上次检查点，恢复不会延长到当前时间。

## 订单关联

选择来源应用、平台和平台账号标识，再启用自动关联。账号标识应与文件账单导入一致；第三方应用切换账号时须相应调整规则。规则针对后续采集生效。

订单号／交易号在主体、平台与账号内关联，待付款、已付款、退款等页面材料持续补充来源。只有某一页同时明确出现订单号和交易号，且不存在字段或账目冲突时，才合并此前分开的身份。

“证据完整时自动记账”默认关闭。启用后还要求当前写入权限、明确支付成功、实付、付款时间、实付对应的人民币证据以及平台使用的规范身份：电商使用订单号，支付与通用平台使用交易号。其他币种、含混状态、身份缺失或字段冲突保留观察。退款材料不单独生成一笔未经证实的退款账目。

记账复用已有账单暂存、候选确认和身份去重，不另建旁路账本。与文件导入发现同身份且金额／日期等事实不同，会保留冲突；已经确认的账目不会被新页面自动改写。Ledger 迁移围栏生效时整笔操作不提交，客户端保留队列等待重试。

## 分层回顾

后台每五分钟处理有新增／修改／删除来源的日期，也支持手动生成。日回顾包含小时与十分钟材料；周回顾汇总到小时；月回顾汇总到日，避免大月份重复展开所有页面。点击来源可读取当前仍可见的原文。

回顾是基于采集材料的确定性整理，未采集时段保持未知，不据此断言真实生活的全部情况。跨期区间裁入所选时区的期间，归入本期起点所在片段；不重复计算跨片段活动。

内容签名变更后旧回顾显示失效提示并隐藏旧正文和来源标题；后台或手动重算产生新修订。来源不变不增加修订。每个窗口最多 50000 项来源；超限返回明确错误，后台某一层失败不阻止其他层更新。录音按 100 段分页，可继续读取更早片段。

新增接口遵循共同合同和 Executor；查询为 `life.capture_workspace`、`life.activity_source`，写入包括 `life.register_recording`、转写处理／更正／删除、`life.set_order_capture`、`life.capture_screenshot` 和 `life.generate_activity_review`。迁移为 `0052_capture_suite.sql`，Android Room 升级到 8。

快捷截图见[参考与操作说明](../research/android-capture-shortcuts-2026-10-30.md)；交付验证见[执行记录](../execution/android-life-capture-2026-10-30.md)。

## 分类、项目与目标

“分析与设置”按日／周／月查看应用、行为、生活领域、项目投入及明确目标。时长以采集区间并集计算，重叠来源不重复累计；只说明已采集部分。系统先采用来源应用类别与内容线索分类，无法判断时显示未知。来源详情可更正行为、领域和项目，并可记住该应用的默认分类；人工更正不会被重分类覆盖。

时间目标复用 Life 的个人意图，可按天或周设定最低／最高分钟数，修改或停用后保留修订。回顾同时读取有权限的餐次、消费与健康摘要；不会把页面观察算作已确认领域事实。首页展示采集时长、应用使用与待同步数量，记录入口可直接进入采集页。

搜索支持日期、文字、来源、应用、分类和项目，分页读取历史。时间线、共同搜索和 Agent 上下文可引用当前可见的采集来源；删除后旧引用不可继续读取正文。

## 本机、同步与处理控制

采集源开关、本机材料上传和服务端处理分别控制。本机暂停同步后，普通 Life 命令仍可同步；账号切换或暂停上传会在分块上传时再次检查。设置显示本机加密队列、处理积压、近期删除、音频与图片大小。已提交的本机采集缓存在七天后清理，未提交材料不受影响。

服务端默认每日最多处理 120 分钟音频、50 张自动截图，按 UTC 日计数，可改为零暂停该类处理。关闭处理使运行尝试失效，旧结果不能覆盖新状态；用户从资料页主动重试属于显式处理。保留天数默认不设定，只有用户启用后才清理到期屏幕材料或已成功转写且不被其他材料引用的录音原件；保护的材料不清理，转写文本继续可检索。

## 本地处理器

转写可以使用[本地模型配置](../../server/worker/config/transcript-local.example.json)。在仓库外建立 Python 环境，安装 [transcription-requirements.txt](../../server/database/python/transcription-requirements.txt)，预先下载兼容 faster-whisper 的模型；`python`、`model_path` 指向绝对路径，`model_id` 标记版本，`expected_model_bytes` 可检查权重文件大小。运行时使用 CPU int8，默认两个线程和本地 VAD，禁止运行时下载模型。音频通过标准输入传入，不生成明文音频临时文件。

截图 OCR 可使用[本机 Tesseract 配置](../../server/worker/config/vision-local.example.json)，安装 `chi_sim`、`eng` 语言包。`SHADOW_LIBRARY_PROCESSOR_CONFIG_FILE` 只指定配置路径；API 与 Worker 使用一致配置。识别文字保留来源与未知字段，不据 OCR 自动证明交易成功；订单自动记账仍受强身份、明确付款证据与用户开关约束。

## 导出与恢复

在系统文件选择器中导出 ZIP，可选附带允许访问的图片和录音原件。每次最多 31 天，支持分页抓取；包含来源 JSONL、修订、时区、分类、校验值和完整清单，末尾完整清单缺失的文件不能恢复。单包最多 10000 项、4 GB，原件单项最多 10 MB。

恢复先把文件复制到账号绑定的加密暂存并完整校验，再分批进入现有队列；同账号重复恢复同一归档收敛为相同副本，后来修改的分类和保护标记不被重试覆盖。录音可恢复已有分段转写，图片可恢复资料关联；不恢复账号凭据、设备权限、个人意图或自动记账规则，不生成交易。中断后可重新选择原包恢复，不能将导出包视为完整账号备份。

共同 API 新增 `life.capture_insights`、`life.capture_policy`、`life.capture_search`、`life.capture_export` 查询，以及策略、分类、目标、保护、恢复与清理命令。准确输入输出见生成合同。迁移新增 `0053_capture_completion.sql`。
