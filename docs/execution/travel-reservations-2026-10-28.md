# 旅行预订与住宿按日查看

## 改动

Web 旅行页把已有预订接入每日行程：可查当天或全部预订，入住、续住、退房、跨夜结束及完全未定时间分别展示。范围外预订日期可选择，旅程第几天仍从真正开始日计算，不开放范围外日计划写入。确认号与座位默认折叠。

新增预订可填写候补、待确认、确认、改签、取消、退款状态以及出发地、目的地、班次、座位；仍直接通过现有 `travel.add_reservation`、Executor 和回执完成。不会因此创建付款、退款或到访记录。

在线与 HTML 离线单共用归日逻辑。只有已确认且起止已知的酒店预订计入当晚住宿，退房日不算一晚；候补与改签不推定已确认。取消/退款记录保留可查。详情和 Bundle 排除误录作废的预订，但保留修订历史。

详情加载失败有独立重试入口，旧旅程响应被中止/忽略；表单与卡片状态按旅程、预订身份绑定。修复本轮验收发现的组件键冲突与窄屏网格最小宽度问题。

## 验证

- `pnpm check` 通过：公开合同生成物、依赖边界、全包类型和常规测试。常规命令中需要数据库的测试有跳过，以下隔离回归补齐。
- `pnpm test:full:offline` 最终 **454/454 通过、0 跳过**。第一次运行 **453/454**，既有 `review-integration` 的“提交后停止”测试在清理时发生 `terminating connection due to administrator command`；同代码复跑全部通过，未改动该测试或 Agent 代码，也不宣称彻底消除了此偶发问题。
- 新增纯函数与离线回归覆盖旅程时区、夏令时重复小时、跨夜结束、酒店入住/退房/续住、不同预订状态、未知起止、范围外日期与 HTML 转义。
- 新增数据库回归覆盖所有者及成员的详情/Bundle、确认号/座位隐藏、私人预订不可见、作废过滤、取消记录保留与修订历史不丢失。
- `scripts/test-travel-reservations-offline.mjs` 使用临时 PostgreSQL、真实 API 和 Vite；浏览器外部网络请求全部拦截。验证日筛选/全部筛选、展开私密字段、添加候补车票后数据库与回执一致，且付款与到访仍为零；验证读取失败后重试、延迟响应不能串到其他旅程。
- 实际检查 1440px 与 390px 页面截图、录入表单、日程与预订操作；检查真实下载的 HTML 在离线时仍可打开。浏览器无页面异常或重复键告警、无外部请求。
- `pnpm build:client` 通过。Vite 保留已有大于 500 kB 的 bundle 提示；本轮没有声称完成包体拆分优化。

## 范围

来源、固定修订、许可与采用/未采用原因见 [研究记录](../research/travel-reservations-2026-10-28.md)。没有复制上游实现，没有新增依赖、配置、迁移、公开合同或 Android 生成物。

本轮交付为 Web 体验与共同查询修复；Android 原生布局、地图供应商、实体设备、真实订单和模型效果未验收。没有部署、APK、生产操作、提醒发送、供应商订单取消或退款执行。临时数据库和测试进程由 fixture 关闭清理；截图仅含合成数据。
