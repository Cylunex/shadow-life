# 支付宝账单标题前置布局

## 问题与修复

原支付宝支出识别仅允许“支出…元”处在全文前三行，适配的是导航与账单标题排在正文末尾的无障碍遍历顺序。导航和“账单详情”出现在正文前方时，完整支出金额被忽略，支付宝订单号也未转换为规范支付身份，采集订单因缺少实付与交易身份未入账。

现在兼容标题末尾的原布局，以及金额位于账单标题后三行以内的布局；标题前的导航节点不影响金额识别。金额前出现商品说明、备注、优惠、金额等详情字段时仍拒绝将其中的文字当作账单头部支出。重复金额、收入、退款、待支付和外币边界保持。回归使用合成商户、金额及订单身份，不保存真实采集正文。

## 验证与上线边界

- 先用新增合成页面重现旧解析结果为空，再修复并验证。
- 内核全套与 `capture-suite` 隔离 PostgreSQL 集成回归共 128 项通过，无跳过；覆盖原采集补记、原账号及来源保留、重复采集复用同一消费记录和仅产生一笔支出。
- kernel/database 类型检查、依赖边界与 `git diff --check` 通过。
- 未部署服务、修改生产账目或构建 APK。既有采集可在服务端上线后，通过 `life.record_captured_expenses` 用原 ID 重解析补记，不能把本地测试通过当作线上已入账。
