# 2026-10-25：MCP 服务端归属与发布准备

用户确认将 MCP 按服务职责放入 `server/mcp/`，并要求调整引用、测试、文档，验证后提交推送及部署打包。
`client/` 现在包含 Web、Android 和 CLI；共享合同仍在 `shared/contracts/`。

## 实现

- 移动 MCP 包，保留 `@shadow/mcp` 包名与 `pnpm mcp` 启动入口；修正 workspace 链接、跨包测试与辅助 fixture 引用。
- 服务端测试范围包含全部 MCP 测试和根 MCP 组合 fixture；客户端范围只排除两份 Web 跨端集成测试，完整套件继续覆盖全部场景。
- 新增 MCP 专用依赖约束：即使位于服务端目录，运行码也必须通过 HTTP 调用 API，禁止导入其他服务端业务实现或数据库驱动。
- 更新目录职责、开发命令和接入文档。历史拆分记录保留当时的归属；本记录说明其后续调整。
- 回归中发现测试连接池关闭与强制删除测试库存在竞态。测试 fixture 现在等待连接实际关闭后正常删除测试库，
  并通过可控的提前返回连接池回归验证；不忽略错误，不修改生产数据库逻辑。
- Android 发布版本递增为 **2.1.29（51）**，应用 ID 和原签名保持兼容。本轮不增加 Agent 编排或模型调用功能。

## 发布边界

线上旧目录布局需要同时切换服务命令、Web 静态路径与外部 MCP 启动器。仓库外发布脚本已补齐独立配置备份、
切换期间固定旧静态根目录、按实际版本选择 MCP 入口、配置原子替换和失败回滚。合成切换及信号退出检查通过，
不把该验证等同于真实回滚演练。

数据库与配置备份、实际部署验证、APK 路径、校验信息及两版本轮换回执统一保存在仓库外运维目录。
真实域名、服务器路径、凭据和生产配置不进入源码仓库。
