# 采集浮条在首帧前退出时的窗口清理

## 问题与修复

摇一摇采集创建无障碍浮条后，如果首屏检查立即报错（例如已锁屏），`WindowManager.addView` 已登记窗口，而 View 首次绘制还未发生。原来以 `isAttachedToWindow` 判断是否需要移除，会跳过这个待绘制窗口。采集任务已结束，残留按钮继续向无人接收的控制通道发送动作，导致取消无效。

浮条关闭改为移除已登记窗口，记录完成状态以支持重复关闭，不依赖 View 是否已经附着。取消按钮在提交取消指令后立即关闭浮条；采集 finally 再次关闭保持幂等。创建时显示首屏读取提示，避免空白状态。

Android 版本升至 2.1.52（74）。延续上一版首屏等待规则：摇一摇只截当前屏，选择自动滚动后才继续。

## 验证与边界

- Robolectric 暂停主线程遍历，复现首帧前关闭、首屏检查异常、取消但采集循环尚未消费三个场景；三项测试在旧代码上失败，修复后通过。
- 应用 154 项单元测试通过，Android 编译和 Debug Lint 通过。
- 签名包、手机安装与现场回执保存在仓库外运维目录。单元测试不代表物理摇动和所有第三方页面的设备验收。
