# 摇一摇采集结果刷新修正

## 问题与处理链路

摇一摇通过 `life.ingest_activity` 携带 `record_expenses: true` 同步材料。服务端在同一次命令内尝试识别付款订单并关联正式消费；满足条件时随命令提交入账，不依赖 Losna 后续处理。缺少必要账单信息、付款状态不符或存在冲突时，仅保留材料，不能把同步成功视为入账成功。历史材料需要补充证据或显式重新处理，日常采集摘要任务不承担延迟入账。

首页曾对新同步记录也应用一分钟读取节流，并等待所有来源详情返回后一起发布结果。因此已入账的记录仍可能显示通用的“采集已同步”。

## 本次修改

- 新提交且尚未读取结果的采集绕过后台刷新间隔。
- 每条详情读取成功后立即显示；保留其他已显示的有效结果，避免被较慢来源阻塞。
- 刷新请求使用代次检查，取消的旧请求不能覆盖新结果或重置新请求状态；仍校验当前账号。
- 区分正在读取入账结果、材料已收录但尚未入账、已入账与读取失败可重试。
- 保留回执验证、批量来源隔离和本地原文隐私处理，不从同步状态推断正式消费。

本次不修改跨来源账单去重规则；缺少共同订单标识的邮件与屏幕材料仍需独立核对。

## 验证与发布范围

- Android `:app:compileDebugKotlin`、`:app:testDebugUnitTest`、`:app:lintDebug` 通过，120 项测试无失败。
- 新增用例覆盖新采集绕过节流，以及慢来源未完成时先发布快来源结果。
- `pnpm check:android-boundaries`、`git diff --check` 通过。
- 本次仅修改源码，未构建发布 APK、未安装手机、未部署服务。已安装版本仍需手动刷新最近记录或打开采集结果查看实际状态。
