# 账单解析、退款防重与核对流程

## 实现范围

- 金额支持末尾“元”和明确京东退款注记，保留原始行及付款总额；零金额与格式错误分开识别。
- 京东明确退款不再被“交易成功／不计收支”兼容逻辑改成支出；原付款的部分退款状态可正常解析。
- 文件自动处理按原分片和行序执行，同来源重复退款在原账与余额检查之前结束；跨分片重复不再因随机 ID 顺序滞留。
- 不计收支的非退款行、闭单和明确零现金流按来源结束，不依赖解析报错。相似退款保留待核对，并区分原账缺失、日期倒置和余额不足。
- `life-operator` 增加按需读取的账单核对流程，覆盖分页、证据优先级、退款关联、保留富明细记录、稳定命令、断点恢复、财务验证与任务／外部事项收尾。入口与接口指南同步更新为 skill CLI。

## 验证与边界

使用合成账单和本地临时 PostgreSQL 验证，无生产业务写入。集成场景验证付款总额与独立退款、跨分片重复、零自费、非现金奖励、闭单、原件关联、回执重放、文件身份复用和相似退款不重复入账。

- `pnpm check`：合同生成物、模块边界、类型与包测试通过。
- `pnpm test:full:offline`：519/519 通过，无跳过；包含临时数据库下的完整跨端回归。
- 解析及策略定向回归 32/32 通过；skill-creator `quick_validate.py` 与本次文档链接校验通过。

解析器版本升至 3，不改变文件身份算法，不重新处理已有批次或改写已完成记录。同日同额不足以证明退款重复，保留的异常仍需按证据显式处理。历史重复记录的作废继续使用既有领域接口，没有新增自动删除或跨项目控制面。

本次不部署服务、不构建或安装 APK，也不切换生产 skill。源码修复和 skill 更新需在后续明确发布后进入运行环境。
