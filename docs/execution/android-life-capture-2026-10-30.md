# Android 自动采集首批实现（2026-10-30）

本批落实[完整设计](../architecture/android-life-capture.md)的采集基础与可选屏幕文字入口。不是全部设计完成，也不包含生产迁移、服务部署或 APK 构建。

## 已实现

- Android“记录”顶部增加“应用使用与活动记录”入口，可按日期读取服务端活动、查看已采集区间时长、加载更多和录入用户填写时长的手动活动。
- 使用情况特殊权限由用户在系统设置授予。支持主动采集及按账号启用的 WorkManager 15 分钟周期采集，读取今天／昨天可用事件；关闭停止后续采集，已经进入队列的记录继续同步。
- 只保存有开始与结束证据的使用区间。跨日裁剪、锁屏／关机结束区间，丢弃无法证实的未结束片段；不把空数据当作全天零使用。
- 屏幕文字由用户在系统启用 Life 服务并选择允许应用后采集。读取稳定页面的可见非编辑文字，排除密码和系统敏感节点；限制深度、节点、字符数。相同应用相同内容在十分钟内合并，内存只保留有界哈希。没有截图、键盘监听或自动操作。
- 屏幕内容保存精确采集时间的点观察，不伪造页面停留时长。页面文字可在 Android 活动列表查看，没有自动创建订单、付款或餐次。
- 复用账号绑定的加密命令队列及同步调度。来源使用独立设备 ID 与稳定 source_id，服务端检查重复身份的内容是否一致；批次冲突整批回滚。
- 新增 `life.ingest_activity` 写能力、`life.activities` 读能力、HTTP GET `/api/life/activities` 与既有 `/api/commands/life.ingest_activity` 写入口，共同使用权限检查、Executor、Operation 与 Outbox。
- `library.item.write/read` 分别控制采集材料写／读。个人 MCP profile 可发现新能力，MCP 与 Android 共享合同；材料不作为经过硬件认证的事实。
- 新增迁移 `0050_activity_captures.sql`，按主体、设备与来源唯一保存活动；查询按日期／IANA 时区裁剪，分页按活动开始时刻与不可变 ID 排序，使用区间并集计算时长，统计与页面处于同一 SQL 快照。

- 全量合同生成、`pnpm check` 和隔离 PostgreSQL 完整回归，完整隔离回归 **457/457** 通过；合同、边界、类型和包检查通过。
- Android `:app:compileDebugKotlin`、`:app:testDebugUnitTest`、`:devices:testDebugUnitTest`；应用 72 项和设备层 8 项通过。
- 新增测试覆盖：来源幂等／重放、身份内容冲突、整批回滚、权限及主体隔离、跨日时长、区间并集、分页、零时长屏幕观察、HTTP 校验、锁屏与缺失结束事件。
- 编译不代替设备验收。尚未授予设备权限、实际采集个人数据、调用付费模型或测量耗电；后台调度、厂商行为、无障碍节点覆盖与账号切换应在主力真机复核。

## 后续与上线边界

- 后续补采集记录修订／删除及防重传复活、用户保留策略、可恢复录音和转写、地点停留、订单付款关联、摘要与目标对照。
- 这批不启用自动入账，不把 screen_text 的模型理解当作订单事实；已有分享原件和账单导入流程继续可用。
- 首批 Activity 页面独立读取新接口，原有跨领域 `life.day` 及业务回忆合同未混入活动中间材料。后续统一展示须保持业务事实和采集观察的类型边界。
- 自动采集默认关闭；启用屏幕读取与允许应用名单的说明包含同步到 Life。当前不提供本机仅记录模式、自动原件轮换或截图 OCR，不能宣传为完整隐私／保留功能已交付。


## 同日继续：采集材料生命周期与订单字段观察

- Android 活动支持另存到资料；服务端通过同一事务复用 Library 写入，重复／并发归档收敛为同一份资料。
- 增加采集删除命令。清除正文、标题和应用包名，保留主体／设备／来源身份与哈希删除标记；相同来源重传不能复活。用户明确另存的资料副本继续保留，删除前在当前页面说明并确认。
- `life.activity_order` 从已保存页面中读取显式标签对应的订单号、交易号、商家、商品、订单金额、实付、退款和时间，区分字段缺失与冲突。采用可复测的确定性解析器，不调用模型、不自动创建收支；Android 可直接查看结果。
- 新增 `life.archive_activity`、`life.delete_activity`、共同查询与完整生成的 Android DTO。新迁移为 `0051_activity_lifecycle.sql`。
- 验证包括归档重复、账号隔离、删除内容清理与重传、保留独立资料副本，以及字段分离、冲突状态和指令式页面材料不触发记账。
- 本轮完整隔离回归 **460/460**、`pnpm check` 通过；Android 编译、72 项应用和 8 项设备单测通过。自动订单身份关联、可靠入账规则、录音／转写、停留地点及分层回顾仍未交付，不以这些字段观察替代完整订单归档。
