# 摇一摇消费入账与历史补录

2026-11-05，Android 2.1.38（60）。

- `life.ingest_activity.record_expenses` 为显式用户入账意图，要求消费与账目写权限；普通被动采集仍遵守原有自动规则，恢复归档不能伪装成主动入账。
- 微信／支付宝无规则时使用各自 default 平台账号；已有规则和旧材料已关联的账号范围保留。解析付款成功、金额、时间、平台身份与人民币通道后复用共同账单暂存、确认、去重及 Ledger 围栏。
- 支付宝区分顶部支出、订单总额和优惠，识别尾部详情标题及平台订单号；微信识别中文日期，以及财付通零钱／零钱通详情中的人民币支出。退款、收入、冲突与字段不全均不自动入账。
- `life.record_captured_expenses` 接收本人原始采集 ID，重新解析历史材料，保留原文、时间和指纹，不通过重传改变原始材料。已存在账目只返回原记录；删除或其他主体材料不可补录。
- 来源详情按账目读取权限提供关联消费 ID，首页能刷新历史补录后的真实入账结果。

验证覆盖：两平台解析、缺失／冲突／退款拒绝、无自动规则的主动入账、并发与重复请求去重、旧材料补录、文件导入交叉去重、权限隔离、操作回放和迁移围栏。部署与真实数据操作由已获授权的运维流程执行，私有原文不进入仓库。

验证结果：`pnpm check` 通过；完整隔离数据库及跨端回归 **503/503** 无跳过；Android 编译、98 项应用单测与 debug lint 通过。
