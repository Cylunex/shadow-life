# Travel 旧项目功能复核（2026-09-24）

对照旧 `shadow-travel` 的旅行闭环实现、规划建议与当前 Life 的 Travel 工作台。Life 已有旅程、版本化日程、地点主题、实际到访、预订、在途运行、轨迹和可携带导出；本次沿用这些事实与 `travel.set_day_plan`，没有另建写入路径。

## 本次完成

- 网页当天编辑器可从已保存地点直接加入停留点，沿用地点 ID，不会把计划转换成实际到访。
- 对同一天草稿中的连续、无时间约束且有坐标的站点给出几何就近排序。已填写时间、主题锚点、已执行站点、无坐标站点维持原位；不跨日期，不自动保存，不改交通或到访事实。建议只调整编辑器草稿，用户可继续移动站点并直接保存。
- 可把现有日程的全部停留点移除并保存为空日；发布出发版本的按钮要求至少一个实际停留点。
- 当天地图按日程标出站点序号，用橙色直线连接连续且有坐标的站点；重复地点保留多个序号，缺失坐标处断开。直线不宣称道路可达。
- 写入继续使用原有命令回执、主体权限、幂等恢复与日程 `expected_revision` 冲突保护。

## 旧项目仍有价值的后续范围

| 范围 | 当前真实状态与依赖 |
| --- | --- |
| 旅行数据迁移与历史恢复 | Life 的便携 Bundle 能恢复新副本，但旧 Travel 的真实生产数据尚未完成所有者映射、来源核对与对账；需要受控真实快照。 |
| 道路路线、实时营业、天气与国际地图 | 几何建议不等于路由结果。精确建议和国际地图需要地图提供方服务、授权与真实网络验收。 |
| 行程离线副本与设备在途验收 | Web 目前有可携带导出，Android 有安全命令队列；旧项目的旅行专用离线 Pack 和真实设备冷启动流程尚未移植，需要独立开发及设备验收。 |
| 共享行程与回忆 | Life 有成员角色和可见性基础，但旧项目的邀请、共享记录流和私密回忆整理尚未移植；这是产品与代码后续工作，不是配置即可开启。跨应用照片选择另需资产授权契约。 |
| 预订原件、邮件与日历订阅 | 预订事实与 ICS 导出已有；原件、OCR、邮件导入和可撤销订阅需要 Archive、邮件及日历等外部契约和授权样本。 |
| 上线使用 | 本次只更改本地源码。真实账号、服务器部署与 Android 安装包均需单独执行，不能从本地测试推断完成。 |

## 验证

`pnpm check`、`pnpm --filter @shadow/web build`、`git diff --check` 均通过。网页单测覆盖排序中的时间站点、锚点、已执行站点、无坐标站点、空日与不修改原草稿，也覆盖地图重复地点编号和缺失坐标断线。未连接生产服务、调用地图付费接口、部署或构建 APK。
