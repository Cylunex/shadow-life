# 数据与定期账单导入优化（2026-10-25）

本轮只扩展 Life 的数据、共同合同与 HTTP 接口。参考用户指定的食记、Personal-Bill，并核对 Actual、Firefly III importer、Mealie、Grocy、OpenNutriTracker；[研究记录](../research/data-import-references-2026-10-25.md)说明一手来源、许可和采用/不采用的规则。

## 已交付

- 通用 CSV/JSON/Markdown 解析增强，并按明确表头识别美团、京东、淘宝、支付宝和微信文本。淘宝续行归单与实付金额分离，原始商品明细保留；未完成状态、退款事件、金额精度、长单号和时区跨日有回归。
- 导入批次增加平台、稳定账号标签和解析版本；候选保留规则前解析事实、当前提案与重复来源。重叠文件、待处理批次和并发确认共同去重，不将无单号同额购买硬合并。
- 迁移 `0048` 恢复旧 Life 平台身份，并保守保留历史未知事件类型；不同迁移 owner key 的旧 Ledger 原件链可正确衔接，按文件批量查询历史映射。已确认账目不会由重导自动覆盖或恢复。
- `money.import_history` / `GET /api/money/imports` 提供主体隔离的来源/状态筛选和精确时间游标分页。批次详情使用只读快照，月汇总统计全部批次并说明展示截断。
- 今日及健康饮食复盘排除已删除餐次；同日空餐使宏量营养完整度保持未完整，明确零值、部分食用与缺失数据仍有独立语义。
- README 保持入口与索引；具体接口、重复处理、来源边界和示例见 [使用说明](../guides/recurring-bill-imports.md)。公共合同生成快照同步更新，没有新增 Agent 编排、提示词或模型调用。

## 验证

- `pnpm check`：合同生成、依赖边界、Android 模块边界、全部 TypeScript 项目与各包测试通过。该命令中的需数据库测试按原约定跳过，完整数据库证据来自下项。
- 最终 `pnpm test:full:offline`：**427/427 通过，0 失败、0 跳过**。使用自动创建和销毁的本机 PostgreSQL，仅合成数据，不继承生产 DSN。
- 升级与定期导入定向验证：**9/9 通过**，包括 pre-0048 升级、旧候选人工更正后的防重、历史账号键不等于原库 owner ID、批量旧原件关联和并发确认。
- 新增历史接口验证覆盖微秒级相同时间分页、后来上传批次排除、筛选/主体绑定游标、鉴权与严格输入、处理状态和数量。
- 新增饮食回归覆盖已删除餐次及历史条目、更新时间、同日空餐、半份食用、明确零值以及主体/日期隔离。
- 最后复查 database typecheck、合同生成和两类边界检查，以及 `git diff --check` 均通过。

复查期间发现并修复了旧 Life 平台分类迁移、旧 Ledger 账号键关联、默认字段改变旧命令指纹、人工更正类型不能充当来源身份四项升级兼容问题。首次全量还发现迁移数量断言需要随 0048 从 47 更新为 48，已更新并完成最终全量复测。

## 覆盖边界

本轮未部署、迁移线上库、导入用户真实账单、创建自动任务、构建 APK 或调用模型。旧 Ledger 历史防重目前保证有完整原件/关联/映射链的美团、京东、淘宝 `default` 账号来源；缺链或无稳定单号不会以相似金额日期代替确定关联。文本解码层限 CSV/JSON/Markdown，不声称支持 Excel/PDF 原文件。Web/Android 交互与 Losna 后续编排不在本次范围。
