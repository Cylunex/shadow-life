# Life 原生计划操作补齐（2026-09-24）

本次继续对照旧 Ledger 的预算、周期事项和消费意向，以及旧 Health 的饮食计划路线图，检查 Life 已有合同和 Android 入口。旧 Ledger 的 `docs/api-contract.md` 记录了预算目标、周期费用和消费意向操作；旧 Health 的 `docs/future-roadmap.md` 将预排餐与购物清单列为待实现路线图，不能把路线图当成已交付功能。

| 领域 | Life 原有状态 | 本次 Android 入口 |
|---|---|---|
| 餐单与购物 | `life.save_meal_plan`、`life.build_shopping_list` 和 `life.update_shopping_item` 已有合同与服务端，原生端只显示数量 | 新建、编辑、复制下周餐单，可补充采购品生成当前版本购物清单，逐项标记买到、跳过或恢复待买 |
| 预算 | `money.set_budget` 与当月进度已有，原生端只读 | 新建总额或分类预算，按当前版本调整金额 |
| 周期费用 | `money.set_recurring_plan`、`money.set_occurrence_state` 已有，原生端只读 | 新建日、周、月、年计划，编辑金额/日期，暂停或继续，并直接处理、稍后提醒或忽略一次到期事项 |
| 消费意向 | `money.set_spending_intent` 已有，原生端只读 | 添加、编辑、取消购买想法；标记已买时关联已有消费记录，不自动生成付款 |
| 次卡 | Life Web、API 已有独立权益与使用明细，Android 只有生成 DTO | 原生创建、编辑、关联原交易、记录实际使用、更正和撤销误记，并支持卡片和使用历史翻页 |
| 身体趋势 | 原生趋势已有期间切换，曲线无法按个人偏好收起 | 按账号保存曲线显示偏好，仅影响图表和概览条，不改变健康事实或手动录入 |

所有原生写入沿用账号隔离的命令队列、版本字段与提交后刷新。次卡购买、使用和实际付款继续保持分离。当前 Android 消费页仍按本月读取计划；跨月计划总览、消耗品使用周期的完整编辑、旧业务数据与原件迁移、实机接入及外部服务配置属于后续独立工作。本次只改代码与文档，不执行部署或 APK 构建。
