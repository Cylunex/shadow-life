# 付款材料归组与闪购长订单设计

## 问题与行为

部分支付成功页只有金额和付款方式，未提供交易号及付款时间。自动采集仅保存材料，后续摇一摇账单详情已正确入账，但首页同时显示两种来源，看起来像重复消费。

新增独立的只读关联字段：在同账号、设备、平台、付款方式、人民币金额及付款后 15 秒窗口内唯一匹配现有消费时，首页归到同一条，并保留采集材料数量。该关联不写入账目、不代替交易号，不删原始材料；后续出现竞争或失效来源时撤回。权限过滤与旧客户端兼容保持。

另整理[闪购长订单方案](../architecture/flash-order-capture.md)：明确商品行/订单实付区域、三种身份、原价/优惠/费用校验、坐标文本块、跨屏重叠与停止条件。长页滚动与分段 OCR 本轮未接入。

## 验证

- `pnpm check`、完整合同生成与一致性检查、内核类型检查通过。
- `pnpm test:full:offline`：独立临时 PostgreSQL 完整跨端回归 523/523，无跳过。
- Android `:app:compileDebugKotlin :app:testDebugUnitTest :app:lintDebug` 通过：121 项应用单元测试，lint 无错误。
- 支付归组覆盖重复账单、竞争记录、不同账号/设备/时区、付款方式差异、明确商家/付款时间冲突、退款、外币、缺少身份、跨午夜、精确 15 秒边界、权限过滤及只读不增加账目。
- 经支持的 skill CLI 只读取得用户指定的两份支付成功页与两份后补账单，在本地回放新规则：匹配两笔不同的既有消费，线上写入次数为零。真实材料仅在进程内处理，未进入仓库。
- 本轮不部署服务，不打包或安装 APK；长页采集仍需按设计实施和真机验证。
