# DatI 参考能力落地

## 实现范围

Life 自身已承接原 Platform/Nexus 的合同、身份、资产、执行、助手会话和上下文职责。本次实现位于 Life，不依赖旧项目。

- 在合同层维护业务术语、同义词、事实边界和六类场景，示例直接复用已有 life-operator JSON。
- `agent.discover`、`agent.glossary`、`agent.scenarios`、`agent.catalog` 通过同一 QueryService 接入 HTTP、通用 CLI、MCP 和内置助手。权限过滤先于排序、术语关联和快照导出。
- MCP 个人配置集中在 contracts，支持可选场景限制；发现、目录、调用和回执恢复使用一致范围，参数不能覆盖进程配置。
- 内置 Runtime 获得三项发现工具的合同和指引；元数据查询不生成保存回执。
- Web 顶部“能力目录”支持任务检索、场景、只读过滤、示例、Schema、纯参数校验、真实执行、耗时、结果及回执。普通写入复用 CommandController；管理和撤销类工具仍使用专用入口。
- 消费详情增加评分、复购意愿、感受编辑，复用已有 `life.correct_purchase`，保留聚合版本、商家、渠道、地点和日期。未知评价不默认填分，不重复记账。
- 合同生成增加目录快照，Web 与 `pnpm catalog:diff` 比较能力、Schema、术语和场景变更。目录随代码发布；比较不触发发布，回退仍使用匹配的完整应用版本。
- 修正全量测试入口的 JSX 配置，使根目录 `pnpm test:full` 与 Web 单包测试使用一致转换。

## 验证

- `pnpm check`：合同生成一致性、依赖/Android 边界、所有 TypeScript 检查及各包测试通过。数据库相关用例在未配置数据库的单包检查中明确跳过。
- 使用全新 UTF-8 PostgreSQL 临时集群运行 `TEST_DATABASE_URL=... pnpm test:full`：313 项全部通过，零跳过；其中本次新增 20 项用例。
- 数据库回归验证参数校验不改变持久状态、评价修正不新增金额事实、同命令重放不重复写入、旧修订冲突、原始信息与历史快照保留。
- `pnpm --filter @shadow/web build` 通过；调试台单独延迟加载。构建仍报告现有主包超过建议体积的提示，不作为运行失败。
- 离线比较相同目录得到零差异；测试覆盖 Schema 和术语改变、能力删除以及权限范围差异。
- 使用无个人事实、禁用写入的本地预览检查桌面与 390px 窄屏布局，验证术语检索、仅校验显示“未执行”、实际查询显示“查询结果”。

本次没有部署、生产访问、付费模型调用或 APK 构建。原生助手通过同一 API/Host 获得发现能力；没有新增原生调试管理页面。架构和使用入口见 [业务语义与能力目录](../architecture/agent-semantic-catalog.md)。
