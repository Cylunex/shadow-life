# Android 整体体验落地与打包（2026-10-30）

Android 版本更新为 **2.1.31（53）**。在[首轮改版](android-experience-refresh-2026-10-30.md)基础上，完成[整体体验设计](../architecture/android-experience-design.md)的页面组织和现有能力交互落地。首页称重卡片保留，健康保留绿色；Losna 仍按用户约定后续接入。

## 本轮补齐

| 范围 | 实现 |

| 计划 | 日程／项目／目标三个主分区；支持指定日期、未来七天、按时间查看事项、折叠历史项目；训练、维护和回顾保留独立入口。 |
| 资料 | 长正文可选择复制；HTTP(S) 链接可打开；受保护图片支持缩放和平移；原件可通过系统保存位置选择器导出。原件与处理内容分开，保持既有服务端权限。 |
| 健康 | 保留健康指标配色；趋势图可点选真实测量点，显示时间、数值、单位与来源；提供现有测量列表及详情。大字体下指标改为单列。 |
| 饮食 | 创建餐次和食材规划分别组织；本餐已有食物可在同一编辑器逐行更正名称、份量与营养；保留未编辑营养和原有依据，不推算未知值。 |

| 草稿与表单 | 常用录入和详情更正草稿按账号加密保存；明确提供保留草稿、放弃及继续编辑。食物行完整恢复；规划和次卡编辑身份、原修订及餐单行随界面重建保存。 |

## 领域语义和实现边界

- 不改变公开合同、服务端执行器或数据库。食物更正复用既有 `life.correct_intake`，逐条携带原修订和稳定命令身份；部分行入队后重试不会重复创建新命令。
- 食物名称变化时解除旧食物目录引用，用户可核对已有营养。未编辑的膳食纤维、钠、实际摄入比例、来源与估算依据保留；未知数值保持未知。
- 原件保存是用户显式选择本机位置的导出，使用账号授权读取；账号切换中止导出，失败清除不完整输出。不会把凭据拼到外部链接。
- 页面草稿不会伪装为已发生记录；保存到本机与已提交分开呈现。设备原生数据仍按既有权限和更正合同展示。
- 不增加模型调用，不改变健康同步、体脂秤协议、持续采集权限及账目统计口径。

## 验证与交付

- Kotlin 编译、Debug 组装与 Android Lint 通过。
- Android 应用 79 项、设备层 12 项单测通过；新增草稿恢复编码、损坏草稿回退、图表点选边界、称重卡保留与食物更正字段保留回归。
- `pnpm check:client` 通过，含合同生成检查、架构及 Android 模块边界、客户端类型检查和 138 项客户端回归。
- Android 35 独立模拟器使用 Debug 专属合成页面验收，不激活账号、不调用真实业务写入。覆盖生活、记录、计划、资料、健康、详情、录入和训练；验证深色、窄屏及字体放大，检查草稿进程重启恢复、失败保留输入和称重置顶。
- Release 使用既有发布配置、Samsung SDK 和原签名；签名、版本、原生能力、对齐、包内目录与 APK 校验由仓库外发布脚本核验，Debug 合成页面不得进入 Release。
- APK 仅保存在本机；按既有保留规则轮换两个有效签名版本，实际签名结果、校验和及清理回执留在仓库外运维目录。未部署服务端。

模拟器验收不代替用户手机上的蓝牙称重、厂商权限、实际地图服务、24 小时后台采集与耗电验收。真实 Losna 对话接入与外部服务质量不包含在这次纯 App 界面发布中。
