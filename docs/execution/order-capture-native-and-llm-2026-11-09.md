# 订单无障碍、美团解析与可控长图

## 改动

- 微信零钱单笔详情的商户标题不再要求固定行号；剔除明确导航及交易服务节点，存在多个候选时保持未知，已有明确商户字段优先。
- 旧外卖观察不再把两个不同订单号连成一个身份；总价减优惠与实付矛盾时，疑似拼接的实付留空，不猜测正确金额。
- 美团原生布局独立解析：订单信息可以先于商品费用，支持空格分组订单号码、分离的货币／数字及数量节点、零元餐具、优惠后配送费与订单合计。合计后截断推荐商品；红包前商品标价不冒充逐项实付，实际用餐与付款仍独立。
- 移除 Android 本地 OCR 及 ML Kit 依赖。美团可读页面通过 `life.ingest_activity` 保存无障碍观察，不截图；其他允许的来源应用（含京东、小象超市、淘宝闪购）使用图像长页或系统长图分享。
- 摇动启动浮条，由用户点击下一屏、完成保存或取消。下一屏才向上滑动，完成保留最后已读取视口，取消不提交；完成与取消为终态。图像仅以重叠像素对齐，无法可靠拼接时保留前面的可靠范围。浮条不获取应用焦点，固定读取原始应用窗口，截图前隐藏浮条。
- 长图／分享图片可选择 Losna 自动识别、默认或指定 LLM、仅保存后手动识别。模型列表由服务器配置提供，只传回 ID 与名称；图片识图路径不回退 Tesseract。多图分享保留 Losna 批次；原件、候选及处理器来源保留。
- 公共截图合同、工作区模型列表、Android 生成物及视觉 Worker 同步更新，未新增数据库迁移。模型缺失、处理暂停或预算不足时保留原件。

## 发布及边界

本轮只修改、验证并提交源码，没有构建 APK、安装手机、部署服务、迁移生产配置或重处理历史材料；手机上旧版的 OCR 行为仍需安装新版本后才改变。浮条触控、各来源真实滚动效果及像素拼接仍待新版本真机验收，本次节点只读回放不等同于安装验收。

LLM 配置示例为 [vision-llm.example.json](../../server/worker/config/vision-llm.example.json)，使用既有 `shadow.library.vision.request/response` 视觉服务协议；端点应连接兼容该协议的 LLM 视觉服务，不能将普通聊天接口地址直接当作此端点。实际 JSON、Token 文件及运行值置于仓库外。具体模型由部署配置指定；尚未配置时选择 Losna 或仅保存，不能把“进入队列”当成识别或入账成功。

完成按钮控制到当前完整视口，未提供半屏裁剪线。每次最多 12 屏／5 分钟，截图高 18000 像素、面积 2400 万像素、上传 10 MB；超限或对齐失败不伪造连续长图。用户主动提前完成的美团材料可以不完整，缺失项保持未知。订单及图像候选不自动增加第二笔支出。

## Android 2.1.48 真机修正

- 普通美团外卖已在已安装的 2.1.47 上完成无障碍真机采集，读取商品、合计及费用，没有图片或重复付款。
- 小象超市零售 MSC 页面不再进入普通美团的节点读取分支；淘宝、京东等同样直接准备长图，不以是否有无障碍正文作为截图前提。
- 第三方无障碍节点读取使用单个有界后台线程，800 毫秒内未返回即放弃该次结果；不阻塞手势／服务主线程，不积压读取任务，迟到结果不覆盖新会话。首次无可读文字可进入长图，后续读取失败保留此前文字。
- 增加仅含应用、路由与通用状态的摇动诊断，截图错误记录系统错误码，不记录页面原文或账号凭据。订单缺失字段不显示 `null`。
- 新增零售／外卖分流、第三方读取阻塞及不可用读取的回归。Android 应用测试 144 项、编译及 debug lint 通过；本次为 Android 修正，服务端合同不变。打包安装与长图真机复测记录在工作区运维回执。
