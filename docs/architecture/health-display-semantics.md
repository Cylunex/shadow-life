# 健康展示语义与起飞记录

Android 为主要客户端。本次在健康、饮食原生工作区提供语义颜色，并增加健康 → 起飞页面。

## 颜色与参考范围

- 蓝色：偏低；绿色：合格；橙色：偏高；灰色：缺数据或没有适用参考。不只靠颜色，卡片和趋势点旁保留文字。
- BMI 默认使用中国成人范围 `18.5 ≤ BMI < 24 kg/m²`。已有有效成年身高档案时，同步换算体重参考范围。其他身体指标不凭空设正常值，用户可在身体页为当前指标设置适用的上下限。
- 睡眠以 18–60 岁成人至少 7 小时为明确标注的通用参考，只显示是否达到参考，不把睡得更长判为异常。此处比较主睡眠，补觉单列。
- 步数、活跃时间和活动热量可点击设置每日目标，达到目标后继续保持绿色；不设“运动过量”阈值。
- 热量仅与用户自定范围比较。蛋白质、碳水、脂肪按已记录且营养齐全食物的供能占比分别比较 `10–35%`、`45–65%`、`20–35%` 成人参考；供能按 `4/4/9 kcal/g` 计算。它不证明当天摄入完整或总摄入足够。
- 有食物缺少任一宏量营养字段时，占比不分级。热量缺项不分级；真实零值和缺失保留区别。
- 自定义范围是当前设备当前账号的显示设置，不修改健康事实或服务端健康目标。恢复默认后回到通用参考或未评级。

- [国家卫生健康委员会：保持健康体重知识要点](https://www.nhc.gov.cn/jkj/s10045/200907/943149b60565497bb3e25783a0e3de68.shtml)

## 三星数据的展示利用

检查现有 SDK 同步和投影字段后，复用已存数据，不新增设备权限或改变同步写入：

- `health.trend` 增加可选 `original_field`；Android 按原字段拆分全天最低/最高心率、最低/最高血氧及手腕皮肤温度，卡片、趋势和详情沿用一致名称。
- 不将全天心率极值当作静息心率，也不将皮肤温度当作核心体温。没有适用参考时保持灰色。
- 睡眠展示最长主睡眠和其他时段，保留分期与未知状态；其他时段合计明确可能有重叠，不制造去重后的睡眠量。
- 运动明细显示原有平均心率、自动识别标记和主观强度。只有正距离和正时长才派生步行/跑步/徒步配速或骑行平均速度，不对不同运动的速度做统一好坏判断。
- 活动热量说明采用设备汇总还是运动合计，沿用服务端去重口径，不叠加两份消耗。

## 起飞页面与查询

`health.release_history` / `GET /api/health/releases?from=YYYY-MM-DD&to=YYYY-MM-DD` 是只读查询，沿用 `health.measurement.read`、服务端主体范围和 QueryService。日期窗口最多 366 天，列表最多 1000 条；即使截断，次数和有记录日期数仍由完整窗口计算。

页面按月提供日历、次数、有记录日期数、月内最近一次、记录日期平均间隔及可点击明细。空白日表示未记录，明确否认单独标记。日期型记录不制造午夜时间，三星原有开始时间按事实时区显示。间隔仅描述已有记录，不给频率设健康评分。

读取 `health_habit_logs` 中有效的 `release`，并关联其已归一化的**同一 raw_version**取得开始时间和时长。待归一化的新修订不会污染显示；修订回普通运动、删除或停用的记录不会被计入。没有数据库迁移或历史事实重写。

## 验证与边界

覆盖 BMI 临界值、未知值与单位不匹配、目标超额仍达标、营养字段缺失、零供能、配速除零、三星原字段分流，以及起飞记录的主体隔离、日期窗口、同日多条、否认、截断、待处理修订、改回运动和删除。
