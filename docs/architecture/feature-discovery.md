# 在 Life 找到要看的页面

2026-11-03 · 导航设计提案。审查基线为 c827c93，覆盖 Android 四个主页面、领域和采集工具，并核对 Web 已挂载分区。以下现状来自源码走查；点击数是下一轮验收目标。

## 最应该先修的入口

| --- | --- | --- |
| 从首页搜睡眠 | 放大镜打开“记录”；在“全部功能”搜睡眠，命中“记录健康数据” | 首选“睡眠趋势”，其次“手动记录睡眠”；有权限的历史记录单列 |

| 看某笔到期账单、某天的健康安排 | 计划日程已有目标 ID，但消费事项与健康习惯回调打开领域首页 | 已有目标与日期则定位该事项；已取消或不可见就留在原日程说明状态 |

## 首页、搜索和领域页如何配合

首页日期下保留固定的“全部功能”，将现有放大镜换成带文字的“搜功能或记录”入口。优先复用当前入口占位，编辑首页收进首页菜单。底部继续用生活、记录、＋、计划、资料；加号只管新增。领域卡可隐藏，固定入口与搜索仍可用。其他三个根页由原有更多菜单进入同一目录；记录和资料页的搜索框保留本页范围，提供“也找相关功能”。

打开“全部功能”默认可直接浏览。第一组常用入口为健康趋势、饮食日记、训练，之后按“健康与运动、饮食与食材、消费与物品、旅行、计划与回顾、资料与采集、设置与设备”列出。每组在折叠标题旁列两三个具体例子，如“消费与物品 · 次卡、账单、保修”。展开后使用紧凑列表，每行一项，右侧显示“查看”“记录”或“设置”。常用入口后续允许手动替换，排序稳定。常用并不等于新增一套页面。

打开首页搜索即聚焦输入。输入“体重”时，功能区依次列“体重趋势 · 查看”“记录体重 · 记录”“接收称重 · 设备”；下面独立显示有权查看的记录。输入“购物清单”只点一次结果就看到清单标题及待买项。标题精确匹配优先，其次是生活用词，再是领域名；每个结果最多一行位置说明，如“饮食 › 食谱与食材”。离线时本地功能结果立即可用，历史记录区明确暂不可查询或显示已有缓存范围。零命中保留输入，并提供“按分类浏览”。搜索只负责进入页面或打开表单；点击“接收称重”落在有“开始接收”按钮的设备页，查找动作本身不会启动设备。

## 不记名字也能找到的路径

| 领域 | 在领域里能看见的入口 | 从目录或搜索直达时的处理 |
| --- | --- | --- |
| 健康、睡眠、称重 | 健康首屏显示身体、睡眠、活动、专项记录与设备来源 | “称重记录／体重曲线”定位身体的体重指标；“昨晚睡了多久”定位睡眠；专项沿用原称呼作别名 |
| 饮食与运动 | 饮食日记旁放“食谱与食材”；训练入口同时显示动作库；快速记录提供补记 | “菜单”给训练菜单与餐单两个带领域名称的结果；“昨天午餐”优先给对应日期餐别 |
| 消费与物品 | 消费管理入口旁列“次卡、订阅、账单核对”；物品可由分类目录进入 | “理发卡／课时”开次卡列表；“扣费／续费”开周期事项；“保修／说明书”开物品选择 |
| 旅行 | 旅程内一直能看到行程、预订、地图；地图另有领域入口 | “酒店／车票”先选旅程再定位预订；从当前旅程发起沿用该旅程。保存到资料的票券另列 |
| 计划与回顾 | 计划保留日程、项目、目标；记录页提供“按日回看”及“生活回顾” | “这周要做什么”开七日日程；“生活回顾”直达回顾列表；“项目”区分生活项目与其他 Shadow 项目 |
| 资料与采集 | 资料搜索与原件筛选就地可见；记录页列“应用使用、录音、地点”等采集入口 | “录音／转写”“截图”“订单关联”“采集导出”分别进入对应采集分区；“说明书文件”同时可搜资料 |
| 设置与提醒 | 各根页更多菜单保留提醒、设置；健康设备状态旁可看来源 | “手表同步”进入设备状态；“同步队列”进入账号队列；“提醒”进收件箱。“其他项目”独立标示为离开 Life |

每一项有一个规范目的地，可由多个词和多个页面进入。必须选原对象的任务使用现有选取列表，显示最近对象和搜索；已有上下文直接沿用。无记录时仍能打开对应页和看到空态。设备未接入与当前端未实现分别处理，只展示当前端可兑现的操作。Android 的健康与饮食联合复盘需另接已有查询，接入前只展示已经存在的按日营养和健康页面。

## 实施与验收

1. **第一批先消除错跳。** 扩展现有 FeatureEntry，让查看类目的地可携带领域、分区及预选指标；用 WorkspaceRoute 的既有 tab 打开 sleep、body、planning、cards、reconcile、map。可立即补上独立的训练、物品、提醒路由。先交付“睡眠、食谱与食材、次卡、物品、训练、账单核对”，逐条检查目的页标题和选中分区。
2. **第二批直达页内目标。** 给训练、采集、设置、饮食长页增加可恢复的子分区或锚点，路由携带稳定键；异步加载后定位一次。旧无参入口仍打开原默认页。加入有类型的搜索结果和别名，目录、首页搜索、页面内快捷入口引用同一目的地。设备可用性、构建开关和账号能力先过滤，普通导航不额外申请权限。
3. **第三批补两端与返回。** Web 次卡在“计划 › 次卡”，Android 在“消费 › 次卡”；两端搜“理发卡”各开本端对应页面。复用 Web 既有 tab/section 链接，用户主动跨页产生可返回的历史项，筛选更新保留当前项。Android 从搜索进详情后返回恢复关键词、分类和滚动；从外部链接进入则按领域父级返回。沿用平台的返回栈规则。[Web 分区与 URL](../../client/web/src/main.tsx) · [Android 导航原则](https://developer.android.com/guide/navigation/principles)

验收使用空账号、有历史账号、首页领域卡全部隐藏三套状态。以“看昨晚睡眠、继续训练、找购物清单、查理发卡、查保修、听录音、看酒店预订、找生活回顾”为盲找任务，给测试者任务句，不告知页面名。分别记录首次点击、最终落点、回退次数与是否需要提示。验收目标为八项均能无提示完成；已知功能从生活页经搜索最多两次导航点击到正确页或必要的对象选择器（输入文字单计），按分类浏览最多三次。同一对象从目录、领域页、搜索三处打开应有相同标题与数据。另测窄屏、大字、读屏焦点、离线、连续切换账号及系统返回。实施后再记录实测结果。
