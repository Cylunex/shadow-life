# 次卡与服务权益

购买和付款仍使用既有消费记录；`money.save_service_card` 把次卡关联到原记录，不生成第二笔付款。
理发卡、洗车卡、整数课时包通过总次数、单位、商家、开始日期、可选有效期表达服务权益。
续购建立新卡并关联新购买；购买不能证明已经使用，也不自动从历史消费或饮食摄入推断扣次。

`money.record_service_card_use` 记录明确发生的日期与使用次数。传入原 `use_id` 可以更正或撤销误扣。
创建、更正、撤销均锁定当前用户的卡片并核对卡片版本，与 Operation 回执和 Outbox 同事务提交。
每次成功写入推进卡片版本，保留被修改卡片和使用记录的旧快照。相同命令键重放不重复扣次。
余额从全部有效使用明细重算，不保存可直接改写的余额，也不会因翻页、关闭、到期或修改记录丢失。

领域校验位于 Kernel：禁止超额使用、未来使用，以及早于开始或晚于有效期的实际使用；修改总次数
和有效日期也不能使已有使用事实无效。已到期卡仍可补录有效期内发生的历史使用。关闭后禁止新增
使用，但保留历史纠错能力。日期为卡片时区的自然日，有效期当日可用。支持正整数次数，暂不建模
储值余额、分数课时、卡间转移或自动续费。

`money.service_cards` 可按卡名、商家、原消费记录或卡 ID 查询，卡列表使用 `next_after_id` 翻页。
按 ID 查询包含最多 100 条使用明细；`next_uses_before_id` 指向下一页。所有页面余额都包含全部
有效明细。卡片只按调用者主体读取；购买关联验证所有权与有效状态，关联需要原消费读取权限。

Web 的计划 → 次卡提供创建、编辑、关联原交易、使用记录、更正、撤销和历史翻页。API、CLI、
内建 Agent 与 Hermes MCP 共用公开合同和 Executor。Android 合同 DTO 同步生成；本次不构建 APK。

迁移 `0040_service_cards.sql` 仅新增表和索引，不改写既有购买或付款。回滚应用可保留新表；只有
确认需要删除新次卡数据并备份后才使用 `migrations/down/0040_service_cards.sql`。
