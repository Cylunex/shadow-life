# 淘宝闪购长订单采集与付款材料归组

## 范围与现状

以两种外卖订单布局为依据，设计淘宝闪购（原饿了么）的长页采集。本文不保存用户原图、真实店名、订单号、地址、电话、骑手或支付账号。

当前摇一摇只采集微信、支付宝的可见无障碍文字，不会滚动。通用文字读取器使用广度遍历和字符串集合去重；这适合付款字段预筛，但会丢掉商品行里重复的数量、价格及其对应关系，不能直接用于外卖明细。

本轮已实现支付成功页与已入账账单的只读归组；下述长页采集、外卖明细结构化和图片分段 OCR 是待实施方案，不是已上线能力。

## 订单字段与区域

按顺序读取四个区域：店铺和配送状态、商品行及费用、价格明细、订单信息。遇到“安心权益”“常见问题”即结束，不采推荐商品。收货信息、备注、发票和配送骑手不进入商品或支付字段。

脱敏验收样例：

| 项目 | 订单 A：粉面及配料 | 订单 B：套餐及小料 |
| --- | --- | --- |
| 商品/选项行数 | 8 | 5 |
| 商品行实付合计 | 17.98 | 21.76 |
| 打包费 | 2.00 | 1.50 |
| 配送费实付 | 0.00 | 0.00 |
| 总价 | 46.48 | 50.74 |
| 优惠合计 | 26.50 | 27.48 |
| 订单实付 | 19.98 | 23.26 |

金额统一用十进制定点计算，分别校验“商品行实付 + 打包费 + 配送费 = 订单实付”和“总价 - 优惠合计 = 订单实付”。不把划线原价、配送费原价或任一商品的“实付”当订单总额。已摊入商品行的优惠不能再次扣减。

“特辣”“不要保温袋”作为零元订单选项保存，不自动创建食材或摄入记录。商品原名、规格、数量、行实付、原价和赠品/选项分别保存；营养和实际吃了多少保持未知。

“订单已送到指定位置”是履约状态。“尽快送达”是配送要求，不是送达时刻。下单时间（可能带毫秒）单独保留，不作为付款时间。支付方式“支付宝”不等于支付宝交易号。

## 长页采集流程

1. 在明确的单笔闪购订单详情摇动，创建一次采集会话；从顶部开始，展开价格明细和订单信息，只操作已经确认的展示控件。
2. 使用节点边界建立按屏幕位置排列的文本块，保留重复文字；跨屏保留重叠区域，以位置、邻接文本和商品行结构对齐。不能按商品名或文字全局去重，同名商品可能有多行。
3. 读取一屏后向下滚动，在内容稳定后继续。以订单号、订单信息末尾和终止区域判断完成；限制屏数、时间和总文本量，页面变化、应用/账号切换、锁屏、无进展时终止。截断不能标记为完整订单。
4. 节点不可读时，逐屏截图 OCR，保留每屏坐标和来源；手动分享的长截图使用同一分块识别路径。分块保留重叠，不整张缩小后识别。原图与结构化观察分开存放。
5. 一个会话只提交一份完整观察，保留所用页面/图片来源；后台屏幕监听不对同一滚动会话逐屏另建订单。

至少先在淘宝闪购实际客户端采集脱敏节点样例，确认包名、可滚动容器、商品行层级与末尾标志。淘宝内闪购与独立客户端分别适配；美团使用独立解析器，不拿闪购布局泛化。首次真机验收覆盖短页、长页、折叠区域、列表误触、同名商品、退款和加载失败。

## 三种身份及去重

- 订单平台身份：平台 + 平台账号 + 外卖订单号。
- 付款身份：支付平台 + 支付账号 + 支付交易号。
- 采集身份：设备 + 来源 ID，重试沿用同一个命令 ID。

支付宝账单中的订单号可能是支付交易号，商家订单号也可能与闪购前台订单号不同。只有来源明确提供两端身份的桥接证据，才能持久关联两个平台的事实。不同外部编号不得硬替换；金额和店名相同不作为强身份。

已存在付款时，订单明细补充购买项目并关联现有消费，不再增加支出；是否实际用餐另行记录。缺少强身份时可提供候选关系，但不能据此重复入账。

## 无交易号支付成功页的展示归组（已实现）

成功页可能只有“支付成功”、金额和付款方式，账单详情才有交易号与付款时刻。前者继续保留为原始材料，后者按既有交易身份入账。

`life.activity_source` 新增可选 `related_consumption_record_id`，与真实来源关联 `consumption_record_id` 分开：

- 仅处理带持久化付款采集上下文、无订单号/交易号的成功页。
- 平台、平台账号、设备、时区、人民币实付和明确付款方式必须一致。
- 对比成功页的采集时刻与账单明确付款时刻，要求成功页在付款后 0–15 秒内出现；账单采集可能晚得多，不拿后一次摇动时刻做匹配。
- 仅在当前可见、已确认消费中存在唯一对应记录时返回；退款、冲突、不同账号、无付款方式、超时或候选过多均不归组。所有查询按所有者隔离，缺少金额读取权限不返回关系。
- 每次读取重新计算，后来出现相同时间/金额的竞争记录时撤回；不写入交易身份，不改变金额，不删除材料，不用于触发入账。

Android 首页按真实消费 ID 归组，优先显示已入账账单结果，合并多份本机采集材料的计数。原始材料列表仍保存每次采集，便于回溯。这个计数不是该消费全历史来源总数。

## 验收重点

两个不同金额的成功页与两张后补账单显示为两条消费；重复读取不产生写操作。反向上传、跨午夜、不同账号/设备、同金额近时竞争交易、删除来源、作废消费、缺少权限和旧版本客户端均需覆盖。长页部分还需验证商品逐行金额核对、停止区域和来源保留；未完成这些验证前不能宣称支持闪购自动长截图。
