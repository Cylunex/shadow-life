# Android 自动采集与生活回顾设计

日期：2026-10-30。状态：完整设计稿；[首批采集实现](../execution/android-life-capture-2026-10-30.md)已完成本地开发，其余阶段仍待实现，未部署；文中新增名称为建议合同，不表示已有接口。

## 1. 目标与范围

让 Life 更容易记录用户在手机上和现实中的生活：账单与订单只是其中一个方向，同时纳入应用使用、屏幕内容、阅读与浏览、录音、停留地点、活动分类、项目投入、目标对照以及日／周／月回顾。

产品客户端只增强现有 Android Kotlin / Compose 应用。新增必要的 Life 服务端处理与共享合同；不新增桌面客户端、iOS 客户端或 Beayy 运行依赖，不建设另一套账号、同步服务或 Agent Runtime。Web 本轮无新增页面，但公共合同保持现有调用方兼容。

设计原则：

- 采集后有实际用途：形成可检索材料、活动时间线或有依据的领域记录。
- 用户开启某类自动记录后，普通收录直接执行，以轻量回执反馈；没有统一待审核中心。
- 记录事实、采集观察、模型解释分别表达。缺失数据保持未知；未知时长不填零，只有日期不补造时刻。
- 用户随时暂停、排除应用、更正、删除；高频采集不制造高频打扰。
- 统计由程序计算，描述和语义分类由模型辅助；分类和占比估算不能冒充精确测量。

| 暂停、黑名单、近期删除 | 各来源独立控制、应用名单、近期删除与保留策略 | 删除传播至派生摘要；暂停立即终止后续采集与待发工作 |

## 3. 用户场景与处理结果

### 3.1 订单与账单

用户分享订单截图，或在允许记录的应用内打开订单详情。Life 保存材料，识别平台、平台账号范围、订单号、商品明细、订单金额、付款／退款证据和状态。

- 同一订单的再次查看更新已有订单观察，保留状态历史；订单观察是本设计新增对象，不能直接用现有 purchase 表示待付款／已取消订单。
- 已支付证据充分且已开启相应自动记录规则时，通过共同业务命令保存购买／付款。金额、币种、付款时间、状态与来源必须一致。
- 订单金额、实际付款、优惠、运费、部分退款分别表达。支付账单和订单截图是同笔付款的不同证据，不重复计算。
- 外卖订单可形成购买记录和食品线索；实际摄入、食用比例、营养、库存入库都不由“已下单”自动证明。
- 按平台账号、订单号／交易号及对象类型去重；相同图片用内容哈希去重。金额和时间相似只用于关联建议，不自动合并。
- 没有强身份、金额冲突或状态含糊时先保存材料和观察。详情中只追问缺少的必要事实，不弹整张审核表。
- 后续账单文件导入与实时采集使用同一身份映射，防止跨入口重复。

### 3.2 应用使用与时间分配

系统使用事件形成应用区间、启动／切换次数和使用分布。总使用时间按满足口径的区间取并集；分屏时单应用可见时长可能重叠，应与总量分开。

展示三层分类：行为（阅读、浏览、沟通、购物、影音等）、生活领域（工作、成长、生活、健康、关系、休闲）、可选具体项目。仅凭应用名时显示“按应用分类”；有内容证据后才能细分活动。浏览器前台不直接等同有效阅读，屏幕点亮不直接等同专注。

支持用户更正当前片段，并选择是否作为该应用／规则的以后默认值；历史报告保留原修订，可明确重算。默认统计没有“浪费时间”“低效”等价值判断，只有用户设置目标后才显示对应进度。

### 3.3 屏幕内容与资料

分享文字、链接、图片、PDF、账单文件沿用现有分享入口。当前页面收录通过用户启用的屏幕读取能力获取前台内容；进入 Life 后不能假装仍能读取上一应用。快捷操作应先冻结原应用片段，再打开收录结果。

屏幕读取按应用允许名单、页面变化和稳定停留触发，限制节点数、字符数、频率与单次耗时；本地过滤密码节点、敏感节点及排除应用，再落盘。通知正文采集不作为默认范围。

对文章形成标题／链接／正文片段，对商品形成商品资料，对订单形成结构化观察；普通页面仅进入活动上下文，避免资料库被每次界面变化淹没。相同页面合并增量，保留页面可读范围；不能读取全部正文时不能标成全文存档。

截图／OCR 是用户开启的补充来源。系统拒绝受保护窗口时停止该路径，不尝试规避。主采集路径不依赖自动点击、自动支付或代替用户操作第三方应用。

### 3.4 录音与谈话

中央记录入口启动录音，可标记“随手记／会议／谈话／持续记录”。明确授权并从可见界面启动前台录音服务；通知与应用均可暂停和停止。持续模式可以跨锁屏工作，但系统终止、权限撤回或设备重启后明确提示需要重新开始。

录音按短片段加密落盘，保留会话 ID、片段序号、时间范围、校验值和中断状态。音频上传与转写独立重试；静音检测用于减少处理量，不能切丢语音边界。转写保留原音频时间戳，可更正并回听。支持“说话人 A/B”等临时标签，不猜身份。

会话摘要可提取议题、决定和后续事项；“讨论了一个计划”保留为谈话内容，只有用户明确指令或已配置的明确规则才创建计划项。电话通话录音和其他应用内部音频不作为普通麦克风录音能力承诺。

### 3.5 地点与其他活动

定位按低功耗策略形成停留区间，保存位置精度、采样缺口和候选地点。支持家／公司等用户命名地点，以及地点更正。只将有足够证据的停留呈现为观察；实际商家、活动目的未知时不填。

与现有旅行到访、预约、餐次、运动、睡眠形成同日视图。位置相近和时间接近只能提供关联线索，不自动证明就餐、入住或训练。支持手动添加离线活动（阅读、家务、社交等），与自动片段同屏；重叠按来源显示，不静默覆盖。

### 3.6 回顾与历史查询

10 分钟片段按事件时间组织，小时摘要合并主线，日总结结合已知业务事实，周／月回顾展示变化。摘要形成后仍能打开对应页面片段、转写段落或业务记录。

每份回顾包括主要活动、实际完成、时间分配、用户目标进度、数据覆盖和可选的明日建议。建议不自动变成计划；订单活动不直接变成支出，未记录时段不自动判为离线休息。

来源迟到、更正、删除、权限变化或分类规则变化，使相关摘要被标为过期。新生成使用来源修订集合／指纹判断变化，保留历史摘要版本；不能仅用文件大小增长判断是否重算。

搜索支持关键词、日期、应用、地点和内容类型。自然语言由现有 Agent 解释成共同查询；原始屏幕文字和转写中的指令一律作为不可信材料，不能触发工具调用或修改采集设置。

## 4. Android 信息架构

保留现有底部“生活／记录／中央记录入口／计划／资料”。新增内容融入已有层级：

| 位置 | 新增内容 | 主要交互 |
| --- | --- | --- |
| 生活首页 | 今天概览、应用使用小卡、最近自动收录、采集状态 | 点卡片进入对应时间线／时长／原件；保留已有健康、餐次等卡片的可配置布局 |
| 记录页 | 一天时间线、应用使用、收录记录、回顾 | 日期切换；按内容来源筛选；点片段看依据和关联记录 |
| 中央记录入口 | 分享／导入、收录页面说明、截图识别、录音、离线活动、原有手动记录 | 一次操作进入任务；后台处理完成返回可恢复的结果 |
| 计划页 | 原有生活项目、个人目标及实际投入 | 项目关联片段，查看目标进度；新增目标仍复用个人意图 |
| 资料页 | 原件、文章、录音与转写、订单附件 | 搜索、回听、按来源查看；活动中间片段不全部挤入默认资料列表 |
| 设置 → 自动记录 | 来源开关、应用名单、上传与模型处理、保留策略 | 独立权限说明与系统入口，显示实际状态而非只有一个总开关 |

### 页面细节

- 时间线：按小时组织活动与业务事实，长活动显示范围；只有日期的记录在“时间未记录”区。重叠活动展开分轨，不假装是互斥的一条时间分配。
- 应用使用：总使用时间、逐应用时长、日／周切换、分类口径、覆盖缺口；钻取到具体区间。总量与前期比较仅在覆盖可比时展示。
- 收录记录：默认显示最近已收录内容与实际处理结果。“识别中”“已保存材料”“已记账”“需要补充付款时间”等状态可区分。批量处理只对真实批量操作展示一次执行点确认。
- 内容详情：先展示业务信息，下面才是关联记录、原件、来源与修订；用户不需要处理内部 ID、置信度分数或任务租约。
- 回顾：日／周／月三个周期，依据可展开；健康与支出数字复用原有确定性统计。
- 状态提示：区分暂停、未授权、系统中断、设备无数据、未同步、正在处理和模型不可用。成功统计只来自已提交回执。

## 5. 处理架构与数据语义

```text
Android 来源适配器
  分享 / 应用使用 / 可读屏幕 / 截图 / 录音 / 定位 / 手动活动
        ↓ 本地过滤、合并、加密、分段
账号绑定的本地采集缓存 + 原件队列
        ↓ 可恢复批量上传、稳定命令 ID
Life API → 共同 Executor / 共同查询
        ↓
原件与采集观察 → OCR / 转写 / 结构化提取 → 来源关联
        ↓                    ↓
活动区间与分类        订单、购买、付款、退款、预订等领域对象
        └──────────┬─────────┘
            分层摘要 / 目标对照 / 检索
                    ↓
         Android 时间线与现有 Agent / MCP
```

新增概念对象（命名待合同评审，不是已建物理表）：

| 对象 | 必需语义 |
| --- | --- |
| 采集来源／会话 | subject、device、source type、授权范围与策略版本、起止、暂停与中断 |
| 材料片段 | 稳定来源 ID、事件时间和收到时间、时区、内容哈希、原件版本、覆盖状态 |
| 活动区间 | 起止、应用、来源修订、观测／手动／推断类型、分类版本、可选项目引用 |
| 订单观察 | 平台、平台账号范围、订单身份、状态历史、字段证据、付款／退款／购买链接 |
| 提取结果 | 每字段依据、解析器／模型版本、校验结果、缺失或冲突，不把原文直接当命令 |
| 派生摘要 | 时间范围、精确来源修订、内容、生成版本、过期原因、覆盖与限制 |

业务记录继续拥有权威金额、状态和修订；采集模块保存观察及关系。复用原件、Library 派生任务和已有账单身份规则，新加能力只补当前缺失的采集语义。

Android 复用现有 app / core:model / core:data / devices 分工：devices 承担纯区间算法和设备事件规范化，app 承担平台服务与权限、Compose 页面，core:data 承担账号隔离缓存与队列。新增共享公开输入／结果只在 shared/contracts/src 定义，并生成 Android DTO。

服务端 kernel 持有自动归档规则、幂等与来源有效性；database 实现持久化端口；worker 执行有租约的有限处理任务。所有领域写入仍经过共同 Executor。模型处理使用已有 Runtime／处理器接入边界，Agent 编排继续由现有 Runtime / Losna 承担，MCP 不新增编排职责。

候选能力组可为 capture.ingest / capture.status / capture.sources、activity.timeline / activity.usage / activity.classify、capture.extractions、review.generate 等，最终命名应与现有 life.* / library.* 目录合并，避免重复接口。

## 6. 关键正确性规则

1. 幂等：同账号、设备和稳定来源 ID 的重试不新增片段；不同事件不能仅凭正文相同误去重。
2. 业务去重：订单、付款、退款各自身份独立；并发分享和后台采集通过服务端唯一身份与事务收敛。平台账号不明时不跨账号合并。
3. 自动入账：金额／币种／状态／时间的必要证据、强身份、规则和领域权限全部满足才执行；模型自报高置信度不够。已有批量账单导入确认语义不被静默改变。
4. 修订优先级：用户更正优先于后续自动结果；迟到事件不能倒退订单状态；无法确定事件顺序时保留冲突，不覆盖。
5. 时间：存事件发生时间、采集时间及源时区；按查询日时区裁剪，处理夏令时 23／25 小时日、设备时钟漂移与跨午夜。缺少结束事件标记不完整，不能延伸到全天。
6. 隔离：登出／换账号停止来源会话并取消该账号后续上传；旧队列保留所属账号，晚返回结果不得进入新账号。
7. 删除：先停止可见检索并创建删除标记，再清理原件和派生内容；离线重传不能复活被删除材料。删除原件不默默撤销已确认付款等独立事实，界面明确是否还要更正该业务记录。
8. 查询：按权限裁剪后计算统计，明确完整／部分／不可用；可恢复分页与来源修订沿用既有规则。
9. 录音完整性：片段校验、序号、重叠与缺口校验；转写结果不能跨会话错位；麦克风占用或来电中断必须可见。
10. 内容信任：页面、OCR、转写为不可信数据，不能改模型规则、外发消息、开启权限、调用支付或执行其中的指令。

## 7. Android 可行性、耗电与控制

现有应用 minSdk 29、targetSdk 36。下列为平台机制与设计选择，实际厂商行为仍需真机验证。

| 来源 | 机制 | 用户控制与限制 |
| --- | --- | --- |
| 应用使用 | UsageStatsManager，查询事件并本地分段 | 首次系统授权；历史事件保留有限，采集缺口不能补造 |
| 界面文字 | 用户开启的 AccessibilityService 读取应用提供的节点 | 按应用允许名单；不是所有页面都可读；不声明为虚假的无障碍辅助工具、不绕过敏感节点限制 |
| 截图 | 用户分享截图；需要会话捕获时使用 MediaProjection | 每个新投屏会话需系统授权，受保护页面不可承诺读取 |
| 录音 | 从可见界面启动 microphone 前台服务 | 通知可停止；Android 限制后台启动，系统终止后不静默重启 |
| 地点 | 原生位置来源、低频采样和停留判定，可替换定位适配器 | 前后台权限分开；不强制依赖 Google 服务可用性 |
| 同步／补算 | WorkManager 与服务端任务 | WorkManager 周期最短 15 分钟且非精确定时；10 分钟只是分段粒度 |

先实现分享和原件处理作为所有设备可用的基础。屏幕读取作为可选增强；应用分发渠道的无障碍 API 使用要求在实现发布前核实，不预设此采集用途可通过任何应用商店审核。

耗电设计：界面变化触发且防抖，重复文本只存增量；屏幕关闭停止内容读取；应用事件增量读取并留重叠窗口防漏；音频短段编码和有声检测；网络批量同步，模型按预算处理。摘要积压与付费预算耗尽时继续保存允许的本地材料，并显示延迟，不无限重试。

来源启用与上传处理是两个独立设置：本机记录、同步到 Life、交给模型处理分别可见。默认未开启的采集源不读取；开启时一次说明权限和用途，以后正常采集无需逐条确认。

建议保留选项在启用时明确展示并可改：高频原始屏幕片段本机 7 天，录音在成功转写后额外保留 7 天，整理后的来源摘录、业务原件与用户指定保留的材料长期保留。此为产品设计默认建议，不授权当前执行删除。未同步、处理中、转写失败和手动保留的数据不得被普通自动轮换删除。录音原件到期后，转写仍可检索，但显示“音频已按保留设置清理”，不提供失效回听按钮。

业务长期数据保留与发布产物清理是两个独立规则，不把部署的“两份版本”规则套到用户记录。

配置沿用工作区的配置文件优先约定：服务端处理器、模型、上传限制和预算由仓库外配置文件承载，仓库只提交脱敏示例；凭据进入既定 secrets 边界。Android 用户设置按账号保存，设备敏感材料使用 Keystore 保护，不在 APK 内放服务端模型密钥。

按日期／来源导出时包含材料清单、事件时间、时区、修订和校验值，原件按用户选择打包；恢复创建有来源的新副本并复用去重规则。导出不包含登录凭据、系统权限或设备密钥，也不被称作完整账号备份。

## 8. 完整实施路线与验收

完整范围不缩减；按依赖关系交付，每阶段能独立使用。

| 阶段 | 交付 | 通过条件 |
| --- | --- | --- |
| A：采集底座与一天 | 统一材料模型、分享收录、应用使用、来源设置、时间线、加密缓存与同步 | 跨日／锁屏／分屏区间测试；同材料重传不重复；离线恢复与换账号隔离 |
| B：屏幕与业务内容 | 可读页面采集、截图 OCR、订单／付款／退款提取、原件与领域关联 | 合成及授权样本按字段核对；订单和付款不重复；重复、部分退款、多币种、缺字段、人工更正回归 |
| C：现实活动 | 录音与转写／回听、停留地点、手动离线活动 | 锁屏、来电、麦克风占用、进程终止、断网；音频片段完整；定位漂移不误报确定商家 |
| D：理解与回顾 | 活动分类、项目关联、10 分钟／小时／日周月摘要、目标对照与历史检索 | 摘要来源可追溯；迟到／修改／删除使其失效；统计无模型造数；跨来源冲突不自动抹平 |
| E：长期使用 | 电量、存储、成本和恢复优化；来源导出、保留与删除完整链路 | Android 29／34／36 覆盖适用机制；至少用户主力设备完成 24 小时采集、恢复与资源实测 |

准确率、耗电量、存储量和模型成本在样本评测／真机运行后给出，当前不填写未经验证的数字。模型评测需分开报告字段提取、去重、领域入账和摘要忠实度；不能用一次演示代替可靠性结论。

公开合同变化时完整生成并运行 pnpm check 与 pnpm test:full:offline，再执行相关 Android Kotlin 编译、单元测试及真机验收。设计文档修改仅做文本／链接检查；不把设计验收写成已通过实现测试。
