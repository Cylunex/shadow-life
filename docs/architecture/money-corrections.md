# 账目局部更正

`money.correct_entry` 继续使用共同 Executor、主体权限、`expected_revision`、命令幂等、修订快照和事务回执。
金额、币种、当地日期、时区与更正原因仍为必填项，兼容现有 HTTP、CLI、MCP、Web 和 Android 调用格式。

## 字段语义

- `occurred_at`、`category`、`counterparty`、`payment_method`、`note` 省略时保留当前值，已有空值继续为空。
- 提供字段值时只更新该字段；不接受 `null` 或空字符串作为清空信号。
- 主动移除已有事实须提供 `clear_fields`，其元素仅限上述五个字段。列表不可重复，也不能同时提供被清空字段的值。
- 修改日期或时区后，保留的精确时间必须仍落在该当地日期内；否则整个命令返回字段校验错误，不产生修订或回执。
  调用方需提供匹配的 `occurred_at`，或明确以 `clear_fields: ["occurred_at"]` 改为仅日期事实。服务端不推断新的钟点。

例如，读取当前记录后补备注的输入可为：

```json
{
  "record_id": "record_example",
  "expected_revision": 3,
  "amount": "12.00",
  "currency": "CNY",
  "occurred_on": "2026-09-10",
  "time_zone": "Asia/Shanghai",
  "note": "补充购买用途",
  "reason": "核对备注"
}
```

省略商户、分类、支付方式和交易时间不会删除它们。要删除备注，省略 `note` 并提供 `clear_fields: ["note"]`。

Web 与 Android 详情编辑器将用户主动删空的可见字段转换为显式清空。Android 不编辑支付方式，两个编辑器均不编辑
精确钟点，因此普通备注更正省略这些字段。日期变更与已有精确时间冲突时，需要通过可提供精确时间或显式清空的调用入口处理。
购买记录与付款可以有不同日期、时区及备注；付款编辑读取 MoneyEntry 自身事实，不能用购买事实替代。
付款更正只更新付款，购买记录自身日期、时间和备注保留。

## 兼容与验证

新增 `clear_fields` 不设默认值，不向旧命令注入字段，旧格式规范化结果及幂等指纹保持一致。
旧客户端继续发送原格式；省略字段的行为调整为保留。旧版客户端以省略表达清空时需更新客户端后才能明确清空。
使用 `clear_fields` 的新客户端需要配套的新 API；旧 API 会按严格合同拒绝未知字段。
已提交的旧命令仍回放原回执，不会重放更正，也不会自动修复历史数据。历史恢复需要另行核对并授权执行。

合并与时间一致性规则位于 kernel，数据库在持有当前版本锁后应用补丁、保存原快照，原退款余额、外币关系、金额精度、
并发版本检查和购买付款边界继续生效。不引入新接口、数据库迁移、审批流程或另一条写入成功路径。

回归覆盖备注更正保留未修改字段、显式清空、时间替换与日期冲突回滚、原快照、命令重试、过期版本、跨主体隔离及独立付款。
合同测试验证旧输入无默认值变化、非法清空组合；Web 与 Android 单元测试验证编辑器清空意图。
