## 导航与生活首页

选用附件中的「保留模块工作区，补足返回」方案。Life 已保存每个模块的栏目、滚动位置和搜索状态，服务中心也能直接打开指定栏目。再次更换全局底栏会同时影响这些已交付的路径。[模块导航及已有回归](../execution/life-module-navigation-2026-11-05.md)

- **生活首页**沿用「常用 → 最近记录／消息 → 我的卡片」。紧凑模式把常用收为一行，优先消费、健康、饮食、全部服务；展开可见原八项。最近信息默认两条。用户置顶的秤和身体分析、隐藏项及排列都按原偏好恢复。进行中的称重或训练可在最近信息区显示一条「继续」。
- **模块根页**左上有「生活」入口，标题仍能切换模块。底栏只显示当前模块的固定栏目。**详情页**改为「返回 + 对象名」，返回恢复来源页的日期、筛选和位置。从通知直接打开且没有来源栈时，回到对象所属栏目。服务中心旧入口继续映射到对应栏目或子页。
- **随手记录**放在拇指可及处。生活根页打开「记一餐、记消费、记体重、记运动」半屏菜单，另有「对 Life 说」与更多类型。饮食和消费页的主按钮直接进本领域表单。每屏保留一个主要新增入口；采集控制条出现时为它留出空间。

## 健康

| 页面 | 从上到下的内容与操作 |
| --- | --- |
| 概览 | 日期 → 今日活动（步数、活跃分钟）→ 主睡眠与最近称重 → 最近事件 → 健康档案。今日未同步显示「今天暂无活动数据」；如展示前一天的数值，带绝对日期。无目标时显示实测值，有个人目标才显示进度。 |
| 身体 | 最近称重的时间、设备和体重 → 同次体脂等已测项目 → 选指标看 7／30／90 天 → 测量历史。概览点体重直达已有测量详情，身体栏目用于比较。只按已有同次记录关系归组；旧数据有体重一项就展示一项。参考区间显示单位和依据。 |
| 睡眠 | 醒来日和主睡眠时长 → 分期构成（颜色和名称、分钟）→ 近七晚趋势与实际覆盖晚数 → 晨间打卡。分期缺项保留「未提供」，百分比需有明确分母。没有逐段起止就展示分钟数；单独的平均入睡时间不能还原每晚作息。晨评用点选量表，未选与 0 分分开。 |
| 运动与档案 | 「运动」看近期活动并进入训练或同路线复盘。体检、不适和起飞记录从「健康档案」进入。体检按报告 → 指标 → 已确认可比的历次结果，保留单位、定性结果和原件页。不适按发作 → 时间点 → 程度与备注，允许只知道日期。 |

趋势沿用已有晨重平滑值，标签写「晨重趋势」；普通体重页保留原始点，点击显示时间、数值、单位和来源。有明确算法与可比样本后再引入其他指标的均线。联合复盘独立成页，健康与饮食分别从自己的选中日期进入。已有饮食复盘、晨重算法和 7／30／90 天联合视图保留各自支持的窗口。[晨重与饮食设计](canteen-and-weight-review.md) · [健康显示口径](health-display-semantics.md) · [联合复盘](wellness-review.md)

## 饮食

| 页面 | 从上到下的内容与操作 |
| --- | --- |
| 今天 | 单行周历条，点月份选任意日期 →「已记录热量」及蛋白质、碳水、脂肪 → 当天餐次 → 饮食与体重复盘。热量旁标「3／4 项有热量」，当天完整性另标「部分记录／基本记全／未标记」。只对已取得覆盖信息的日期加记录点。读失败给重试。 |
| 餐次与快记 | 有记录的餐次显示餐别、已知时间、食物份量和小计。有照片时展示缩略图。其余餐次合为「＋早餐」「＋晚餐」等轻量入口。点「记一餐」可选常吃、门店菜品、最近餐次，也可手填。点「照这餐再记」先生成所选日草稿，保留来源信息，保存后生成新餐次。 |
| 餐次详情 | 顶部一个「编辑」入口，内含餐别、日期、备注和已有食物。食物行默认只占一行，点开改原份量、单位和实际吃了多少，提供半份、全份及自填。沿用菜品基准、每餐估重和摄入条目的来源，按实吃比例折算一次。分项更正逐项显示同步结果并保留未完成草稿。整餐增删和一次提交的语义需单独校验合同。 |
| 餐单、食材、采购 | 餐单按天看，点菜进食谱详情。份数切换只换算有数值与兼容单位的原料。库存按实际到期日显示「还剩 2 天」；有批次和数量才提供扣减。采购将待买放上方、已买折叠；要形成入库记录时补齐数量和批次。采购清单与消费共享常购价格入口。 |

例如午餐有三样菜，只知道两样的热量，页面写「已记录 420 kcal · 2／3 项有热量」。点一行即可看到哪样缺数据；「基本记全」只表达用户对当天记录的判断。手动记一顿无需先关联支付。菜品库已支持采用常用份量、档口营养及出处，本轮把这条路径接进主表单。[菜品库](../../client/android/app/src/main/java/com/shadow/life/NativeCanteenProfiles.kt) · [餐次详情](../../client/android/app/src/main/java/com/shadow/life/MealDetailContent.kt) · [现有逐项更正](../../client/android/app/src/main/java/com/shadow/life/MealIntakeEditor.kt)

## 消费

| 栏目 | 页面结构与操作 |
| --- | --- |
| 概览 | 月份与原币 → 净支出（支出减退款，收入另列）→ 待核对、临近到期 → 最近正式明细 → 预算。当前读到分页流水时，主数字紧贴「已加载明细小计」；完整月汇总须有同月份、币种、有效记录的完整读数。订阅到期、待补货按日期或状态筛选后再露出。 |
| 明细 | 正式明细、账单待处理、采集订单各有入口。候选先显示日期、商家、精确金额与状态；点「修改」才展开。退款用搜索选择原交易。重复候选可并排看现有流水与原件。进入某批次后返回应保留月份、筛选及正在核对的行。 |
| 统计 | 将现有订单／商品统计接进消费，饮食保留相同页面的上下文入口。「收支」按资金流水发生日，「购买与食用」按原有订单口径，分别显示时间窗、币种、覆盖数。由商家可下钻到有权限的支持记录；分页样本只能解释所列样本。 |
| 规划 | 原「预算」位置拟扩为「规划」，默认仍打开预算。周期订阅、次卡、消耗品、想买各有列表和详情；原预算直达链接落在预算。次卡可从卡面记使用，看得见本次扣几次；消耗品将实记余量和估算耗尽日分行。 |

**记一笔。** 金额输入框首先获得焦点，常用分类和支付方式在键盘上方直接可选。商家、分类都可按原规则留空。订单行可带着来源去建物品、消耗品或食材批次，用户明确选用途后才写入；已有关联时优先打开已有对象。常购价页按可比商品、单位和币种比较，售后页分别列预计退款、已分配到账和差额。

**核对一笔。** 已确认、候选、仅采到原件分别展示状态。单笔无冲突时在行内确认，待退款关联或疑似重复时先定位具体问题。批量处理另列后续工作，需要可预览范围、逐条结果和重试依据，再在原处确认。Web 当前建批次的表单支持粘贴 CSV、JSON 和 Markdown 表格；Android 首轮沿用已导入批次，文件选择、新格式解析和外币工作区另排。[Web 导入表单](../../client/web/src/MoneyImportPanel.tsx) · [消费及账单链路](consumption-bill-chain.md) · [订单统计的币种、退款及覆盖规则](consumption-statistics.md)

## 视觉、编辑与状态

- **一屏一个主数字。** 沿用健康绿、饮食杏色、消费暖黄、睡眠淡紫，以及纯黑暗色和奶油白浅色。金额右对齐、单位紧邻数值、日期和覆盖范围始终可见。大段解释放进「如何计算」，直接影响读数的「部分记录」「估算」「已加载」留在数字旁。[现有领域配色与排版](event-details-visual-design.md)
- **操作跟着对象走。** 单一状态可原地更新，有可靠逆操作时提供撤销。改一至三个字段用底部面板，整餐、多步录入、核对原件用独立页。对象选择显示名称、日期、金额或来源；内部编号和版本由客户端传递。遇到并发更正保留输入并提示重读。
- **离线与无数据。** 已有缓存显示快照时间，排队写入显示「已存本机，待同步」，收到正式回执在原位置更新。无记录、无权限、暂时读不到、明确记录的零值各有文案。小屏或大字模式将并排指标改为单列，动作有文字名称，图表同时提供可读数值。

## 实施顺序与验收

| 批次 | 可独立交付的范围 | 验收情景 |
| --- | --- | --- |
| 1 · 三个首屏 | Android 模块根页与详情返回、拇指区主动作、健康概览重排、饮食单一日期条与营养前移、消费待处理和统计入口。复用当前查询和回执。 | 在 360 × 800 dp、默认字号下，三页均无需滚动即可读到主数字、日期或期间及适用范围。从生活进入任一重点模块只需一次点击；从饮食当天进入记餐只需一次。服务中心指定栏目、系统返回和首页卡片偏好都有回归。 |
| 2 · 一次完整任务 | 同次测量详情、已有睡眠分期、常吃菜多选与整餐编辑入口、单笔对账与退款选择器；Web 同步三个主流程的层级与文字。 | 早晚各称一次只展示所点那次；补记前日午餐后回前日，半份只折算一次；候选到账后小计按覆盖刷新，重复点击及离线重连只记一笔。Web 键盘可完成单笔核对，刷新后链接仍能打开对应对象。 |
| 3 · 专页与跨域 | 优先体检与不适、次卡与售后、常购价格和采购互通，再排食谱烹饪、训练、出行、物品和采集专页。 | 体检仅在同项及单位可比时出趋势；退款分配有上限；采购行能追到来源，重复转入能定位已有对象；无原件定位、无坐标或无录音时仍有可用文字视图。 |

实施前先核对四处数据依赖：完整月收支、按日逐夜起止、跨订单商品检索、跨对象创建的幂等关联。可直接复用的先上线，缺少的读数在界面使用已有、有范围的展示。新增公共合同按项目约定执行两端生成与回归。真机验收覆盖 320 dp 窄屏、大字号与读屏、深浅色、飞行模式后重连；本轮的线框只用于评审信息顺序和点击路径。
