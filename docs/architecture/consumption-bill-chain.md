# 消费、账单与饮食的查看链路

2026-11-05。Web 与 Android 共用既有 API 和 Executor，保持消费事实、资金流水、餐次与来源的独立含义。

## 统一入口

Web 首页「消费与账单」、功能搜索与记录页「消费」进入同一工作区，默认展示全部消费明细，提供搜索和稳定游标分页。外币与分摊保留为独立分区。Android 消费首屏将最近明细前移，「消费明细」「账单待处理」始终可见，预算等工具保留在更多管理。

| 录入路径 | 在哪里看结果 | 尚未入账时 |
| --- | --- | --- |
| 摇一摇、屏幕采集 | Android 消费 → 摇一摇与采集订单；已入账订单可打开消费详情 | 显示仅收录材料、冲突或缺少字段；不声称已记账 |
| Agent、邮件 Agent | 正式消费明细及原始来源 | 由原 Agent 返回处理状态；本次没有新增 Agent 编排或邮件拉取 |
| 购物／支付 App 导出账单 | 账单待处理 → 批次 → 已入账记录 | 解析候选不计入收支；疑似重复项可打开原记录比对 |
| 手动消费、购买或带付款的饮食 | 消费明细 → 单笔详情 | 无付款的购买标明未记录付款，不计入支出 |

消费列表包含有付款的记录及无付款的购买；同一消费已经有付款时只列一行。查看购买信息仍需要原有饮食／购买读取权限。列表展示正式记录和可查历史状态，不把已作废事实计入金额汇总。

## 单笔详情与饮食

详情将付款、购买明细、关联餐次与来源分开说明。两端可查看来源正文，已有资产可查看／保存原件。仅按已保存的来源标记展示；没有入口元数据时不猜测来自邮件、摇一摇还是手动。

消费可选择已有餐次，通过 `life.link_meal_consumption` 建立 `user_confirmed` 关联。Web 写入后回读详情；Android 经既有加密命令队列同步，区分本机保存与服务端结果。关联不新建付款、不新建餐次、不自动分摊金额，也不把购物清单换算为已吃营养。

餐次反向链接覆盖只有资金流水而没有购买对象的消费，并在关联记录说明中展示手动确认、共同来源或历史引用依据。权限不足时不泄露付款。直接餐次付款和消费关联不会在反向列表重复显示同一付款；已作废付款、已删除餐次不再作为有效关联展示。新的关联只接受同一主体下的有效餐次与已确认消费。

## 查询修复

- `/api/money` 在原有稳定游标范围内并入没有付款的购买，金额保持未知；统计仍基于资金流水。
- 消费详情补齐资金流水自身的来源，以及直接餐次付款的餐次来源。
- 餐次 → 消费的反向查询补齐只有付款的消费，保留来源依据和权限投影。
- 消费 → 餐次只返回有效餐次；餐次付款列表排除已作废流水。

本轮不更改历史业务数据、不自动合并疑似重复账目、不修改自动记账规则。没有证据证明实际食用的订单继续保留为购买。生产验证、服务部署与 APK 打包按独立明确任务执行。
