# 购买与消耗品使用

`life.record_purchase.consumables` 按 `item_position` 在原购买事务中建立待启用周期；存在跟踪项时
额外要求 `money.plan.write`。普通购买不隐式建立库存。Agent 按用户约定决定跟踪品类和排除项，
个人品类偏好存放在运行环境的用户约定中，不写入通用代码。

沿用 use_cycles，新增 `usage_state=pending/in_use`、数量显示单位和备注。原有 state 仍表示周期
是否结束，保持已发布客户端的枚举兼容。旧周期迁移为 in_use，已有饮食匹配行为不变。
待启用的 started_on 是登记/购买日期，没有当前库存或预计耗尽日；启用后改为真实启用日期。

手动模式使用 `money.record_consumable_use` 记录实际日期和统一单位数量。事件不新建金额，
以周期版本锁串行化；更正或撤销保留事件与周期快照。拒绝未来、周期外、跨用户、超额和单位
变更；同一批次不能同时自动匹配饮食和手动扣减。命令幂等与未知结果恢复沿用统一 Executor。

余量按全部有效事件聚合，独立展示“按已记使用剩余”和“按日用量估算剩余”；每天的预计量
不是实际事件。估算使用启用后完整经过的当地日期，已记录消耗与日用量取较大值，避免二次
扣减。克/毫升保持原饮食换算规则，袋、卷、个使用 count 加显示标签，不猜包装换算。

money.planning 仍按月展示相关的最多 100 个周期；每个周期附最近 50 条使用明细与截断标志，
所有历史均持久化，余额不受展示上限影响。补货提醒仍限定有明确摄入匹配和阈值的周期。

账目列表、时间线与搜索统一使用商品名称投影，次选备注、交易方、商家、分类及中文收支类型。
只有具有 life.meal.read 的调用者可读取购买名称；只有账目权限时使用付款自身信息。

回滚应用可切回旧版本。数据库回滚脚本在 migrations/down，仅可在妥善保留使用事件后执行，
不能在已有新业务数据时直接删表。
